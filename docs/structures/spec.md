# Branded structures: the specification

**Normative** for the structures extension, which is the companion of [contract.md](../contract.md)
§ Extensions. Its subject is how a brd14 id's own properties become data structures:
- the namespace becomes the partition;
- the contract's `hash32` becomes the trie route;
- mint order becomes key order;
- mint time becomes the expiry bucket.

The story behind it, its decisions and their rationale are in the
[KAN guide](../kan/brd14-pragmatic-guide.md).

| Structure | Go (`go/brdata`) | Rust (`native/rust/crates/brd14-data`) | Elixir (`ex/echo_data`) | Equivalence |
|---|---|---|---|---|
| CHAMP forest | `brdata.Champ[V]` | `brd14_data::Champ<V>` | `EchoData.BrandedChamp` (+ `EchoData.NativeChamp`) | **shape**: same trie, digest, order |
| Ordered map | `brdata.Tree[V]` | `brd14_data::Tree<V>` | `EchoData.BrandedTree` | behaviour |
| Time buckets | `brdata.Buckets[V]` | `brd14_data::Buckets<V>` | `EchoData.Buckets` | behaviour |

The oracle is `tools/champ_oracle.py`, written from this page alone. The vectors are
`vectors/champ.tsv`, generated by `tools/vectorgen.py` and never edited by hand.

## The forest

All three structures key entries by `(namespace, snowflake)` and keep **one inner structure per
namespace**:
- an inner structure is created on the first put to its namespace;
- it is removed when its last entry is deleted;
- the forest tracks its total size and each namespace's size, so `namespace_size` is O(1).

**Writes by id are loud:** an invalid id is refused with its contract error class and never
stored. **Reads by id are quiet:** an invalid id reads as absent.

<a id="champ-champ"></a>

## CHAMP (the champ)

A Compressed Hash-Array Mapped Prefix-tree over **snowflake keys**, routed by the contract hash
`h = hash32(snowflake)`. Persistent in every language: a write returns a new forest and leaves the
old one unchanged, sharing every untouched node.

### Nodes

There are two node kinds.

**Bitmap node `{datamap, nodemap, data[], children[]}`.**
- `datamap` and `nodemap` are disjoint 32-bit masks.
- Bit `b` of `datamap` means an inline `(key, value)` pair at position `popcount(datamap & (b-1))`
  of `data`.
- Bit `b` of `nodemap` means a child node at position `popcount(nodemap & (b-1))` of `children`.
- The empty node is a bitmap node with both masks 0. Only a root may be empty.

**Collision node `[(key, value), …]`.** It is an ordered list, reached only at level 7, where two
keys have equal `h`.

The fragment at level `L` is `(h >> 5L) & 31`, for levels 0 through 6. Level 6 sees only bits 30
and 31, so its fragment is in 0..3. Beyond level 6 the hash is exhausted.

### get(key)
Start at the root, level 0:
- **Collision node:** the value paired with `key` in the list, else absent.
- **Bitmap node:** let `b = 1 << fragment(h, L)`.
  - If `datamap & b` is set, the inline key is compared, and its value is returned only when it
    equals `key`.
  - If `nodemap & b` is set, recurse into the child at level `L+1`.
  - Otherwise the key is absent.

### put(key, value)
On a **collision node**:
- if `key` is in the list, its pair is **replaced in place**;
- otherwise `(key, value)` is **prepended**.

On a **bitmap node**, with `b = 1 << fragment(h, L)`:

| Case | Result |
|---|---|
| `b` in neither mask | insert the pair inline; set `b` in `datamap` |
| `b` in `datamap`, same key | replace the value in place |
| `b` in `datamap`, other key `k₀` | remove the inline pair; clear `b` in `datamap`, set it in `nodemap`; insert the child `merge(k₀, v₀, key, value, L+1)` |
| `b` in `nodemap` | recurse into the child; replace it with the result |

**`merge(k₁, v₁, k₂, v₂, L)`**, where `(k₁, v₁)` is the pair already stored and `(k₂, v₂)` the new
one:
- **`L ≤ 6`, fragments equal:** a bitmap node with only `nodemap = 1 << f`, whose single child is
  `merge(…, L+1)`.
- **`L ≤ 6`, fragments differ:** a bitmap node with both pairs inline. Since data is ordered by
  bit, the smaller fragment comes first.
- **`L = 7`:** the collision node `[(k₁, v₁), (k₂, v₂)]`, with the stored pair first.

### delete(key)
On a **collision node**, remove `key` from the list:
- if it was absent, the node is unchanged;
- if the list becomes empty, the result is the empty node;
- otherwise the remaining pairs keep their order.

On a **bitmap node**, with `b = 1 << fragment(h, L)`:

| Case | Result |
|---|---|
| `b` in `datamap` | if the inline key equals `key`, remove the pair and clear `b`; otherwise unchanged |
| `b` in `nodemap` | delete from the child, then **collapse** (below) |
| otherwise | unchanged |

**Collapse keeps the trie canonical.** After deleting from a child, the parent inspects the new
child:
- a collision node holding exactly one pair, **or** a bitmap node with `nodemap = 0` and exactly
  one inline pair, is pulled up. The parent clears `b` in `nodemap`, sets it in `datamap`, and
  places the pair inline at its `datamap` position;
- any other child is kept.

The check runs at every level on the way back up, so a lone survivor rises as far as it can.

### Order
Traversal is depth-first and fixed by the shape:
1. a bitmap node yields its inline pairs in `data` order, then each child in `children` order;
2. a collision node yields its list in order.

This is **hash order, not key order**. The forest yields namespaces in ascending byte order, each
namespace's trie in traversal order.

### Shape digest
The digest of a trie is FNV-1a-64 over a preorder serialization, with all integers little-endian:
- offset basis `0xcbf29ce484222325`, prime `0x100000001b3`;
- a bitmap node (including the empty one) is `0x4E`, then `datamap` as u32, then `nodemap` as u32,
  then each inline key as u64 in `data` order, then each child's serialization in `children`
  order;
- a collision node is `0x43`, then the count as u32, then each key as u64 in list order.

Values are not part of the digest. Two tries with equal digests have equal shape and equal
iteration order.

<a id="vectors"></a>

### Vectors: `vectors/champ.tsv`

Columns: `kind`, `case`, `seed`, `ops`, `keys`, `program`, `size`, `digest`.
- `size` is the number of entries after the run;
- `digest` is 16 lowercase hex digits;
- `-` marks an unused column.

**`explicit` rows** carry a `program`: comma-separated `+<snow>` (put) and `-<snow>` (delete)
steps. The value put by step `i` is `i`. These rows pin the corner cases with keys constructed to
collide:
- full 32-bit `hash32` collisions;
- 2-way and 3-way collisions;
- prepend versus replace;
- delete with collapse;
- deep single-child chains;
- deleting an absent key;
- deleting everything.

**`stream` rows** carry `seed`, `ops` and `keys`. The program is derived with SplitMix64. In the
pseudocode below all arithmetic is mod 2⁶⁴:
```
next(s):  s += 0x9E3779B97F4A7C15; z = s
          z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9
          z = (z ^ (z >> 27)) * 0x94D049BB133111EB
          return (s, z ^ (z >> 31))

pool:     s = seed ^ 0xD1B54A32D192ED03
          for j in 0..keys-1:  (s, z) = next(s);  pool[j] = z >> 1
program:  s = seed
          for i in 0..ops-1:   (s, r) = next(s)
                               k = pool[(r & 0xFFFFFFFF) mod keys]
                               if r >> 62 == 3: delete k   else: put k := i
```

**What an implementation must reproduce for every row:**
- the `size` and `digest`;
- every key in the pool (or the program) must read back the value of its last put, or absent
  after its last delete.

**Constructing collisions.** `hash32(k)` is the low 32 bits of `f(k) = g(C · g(k))`, where
`g(y) = y ^ (y >> 33)` is an involution and `C = 0xFF51AFD7ED558CCD` is odd. That makes `f` a
bijection on 64 bits, with `f⁻¹(y) = g(C⁻¹ · g(y))`. The oracle picks outputs `y` sharing their low
32 bits (or only some low fragments) and inverts them, keeping keys below 2⁶³.

<a id="tree-ordered-map"></a>

## Tree (the ordered map)

Per namespace, entries are ordered by snowflake. For one namespace that is byte order of the ids,
which is mint order.

| Operation | Contract |
|---|---|
| `put`, `get`, `delete` | O(log n) worst case per namespace |
| `first(ns)` / `last(ns)` | the smallest / largest snowflake, as an id, with its value; absent for an empty namespace |
| `page_after(ns, cursor, n)` | up to `n` entries with snowflake **strictly greater** than the cursor's, ascending; a `nil`/empty cursor starts at the beginning |
| `between(ns, from, until)` | entries with `min_for(from) ≤ snowflake < min_for(until)`, ascending (half-open) |
| `to_list(ns)` | the whole namespace, ascending |

Elixir's tree is persistent (`:gb_trees`). Go's and Rust's are mutable, with `Clone()`.

<a id="buckets-generational-expiry"></a>

## Buckets (generational expiry)

`bucket_bits = b` sets the granularity: bucket `= snowflake >> (22 + b)`, spanning 2^b ms. Entries
are keyed by **snowflake alone**. The namespace of a put-by-id is checked, then dropped, so two
namespaces must not share a snowflake within one `Buckets`.

| Operation | Contract |
|---|---|
| `put`, `get`, `delete` | two map hops: the bucket is computed, never searched |
| `expire_older_than(t)` | drops every bucket with key `< min_for(t) >> (22 + b)`, i.e. buckets that end at or before the cutoff's bucket starts; returns the number of entries dropped. Entries in the cutoff's own bucket survive even if older than `t` |
| `bucket_count` | number of non-empty buckets |

The cost of expiry is O(buckets), and no entry is visited. Elixir's buckets are persistent; Go's
and Rust's are mutable, with `Clone()`.

<a id="proof"></a>

## Proof

| Claim | Check |
|---|---|
| Champs are shape-identical | each language replays `vectors/champ.tsv`: size, digest, read-back |
| The champ behaves as a map | random op streams vs a plain map model (Go, Rust, Elixir property tests) |
| The oracle is right | `tools/champ_oracle.py` self-test; a prepend→append mutant must fail the collision vectors |
| Tree and Buckets behave as specified | per-language model tests: tree pages and windows vs a sorted list; buckets expiry vs filtering by bucket |
