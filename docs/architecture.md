# Architecture

## One contract, many independent implementations

```
                         docs/contract.md  (normative prose)
                                 │
                       tools/oracle.py  (executable spec: Python bigints, no shared algorithm)
                         │                         │
         tools/vectorgen.py → vectors/*.tsv   tools/parity.py → request file
                         │                         │
   ┌──────────┬──────────┼──────────┬──────────┬───┴──────┬───────────────┐
   go/     native/c/  native/rust/  python/  ts/brd14  ts/brd14-wasm ── native/rust/crates/brd14-wasm
   (ref)   speed      speed         pure     pure      wasm
           memory     memory
           └── native/include/branded_id.h ── native/rust/crates/brd14-ffi (drop-in) ── native/beam (NIF)
```

The implementations share **no code**. They agree because three things hold:

1. The contract page states every rule once.
2. Every suite asserts the same frozen corpus in `vectors/`. The corpus is generated by an oracle
   whose algorithm none of the fast paths use: arbitrary-precision division, not split chains or
   pair tables.
3. The differential parity run sends hundreds of thousands of fresh inputs, valid and hostile, to
   every implementation and compares every byte of every answer against the oracle.

## The variant taxonomy

| Variant | Goal | Where | Technique |
|---|---|---|---|
| **pure** | Readable, idiomatic, the reference | Go, Python, TS | One digit per step, a table or a dict lookup, no tricks that hide the contract |
| **speed** | Fewest cycles per op | C `speed`, Rust `speed` | The value split at 62^6 into two independent divmod chains, a 62×62 pair table (two digits per divmod), a 256-byte decode table, a branchless charset check, and a lexicographic range guard |
| **memory** | Smallest footprint: no lookup tables | C `memory`, Rust `memory` | The same split. One digit per constant divmod. Digit↔char done arithmetically, the charset check by three disjoint range masks, and the range guard arithmetic: `(hi, lo)` vs `(QA, RB)` |
| **wasm** | Native speed inside JS runtimes | `ts/packages/brd14-wasm` | The Rust core compiled to wasm32 with raw exports, fixed memory, and batch entry points |

**Speed vs memory trade-off.** The speed tier carries about 8 KB of read-only tables (a 7,688-byte
pair table plus a 256-byte decode table). That is cheap for a server, but it costs L1 lines in hot
loops shared with other work, and it is real weight for wasm or embedded targets. The memory tier
carries none of it.

Both tiers export the **same C ABI**, so a consumer switches with a build flag and the parity run
holds both to identical bytes.

## Zero allocation

| Tree | Hot-path allocation | Proven by |
|---|---|---|
| Go | **0** for the `Append*`, `Parse*` and `Valid*` families, plus `Hash32`, `Next` and the field readers | `testing.AllocsPerRun == 0` tests; `-benchmem` in benches |
| C | 0 by construction: libc only, caller-owned buffers | `nm -u` shows no `malloc` |
| Rust | 0 by construction: `no_std`, no `alloc` crate | The crate does not link `alloc` |
| wasm | 0: no allocator in the module, static IO region | The module has no imports and its memory is fixed |
| Python | The result object only (`str`/`int`/tuple) | Documented in [python.md](python.md) |
| TS pure | The result only. Parts and bytes APIs allocate no BigInt | Documented in [typescript.md](typescript.md) |

## Directory ownership

Each tree has one owner and one Makefile with the same targets (`test`, `bench`, `harden`,
`clean`). The root [`Makefile`](../Makefile) delegates to every tree and adds the
cross-language targets (`vectors`, `parity`). Shared files (the root README, `docs/index.md`,
`.gitignore`, `.gitattributes`) are edited only by the integrating change, never by a
per-language change. That rule lets the language trees be built in parallel without merge
conflicts.
